= 模块 3：mTLS 微服务通信
:navtitle: 模块 3：mTLS 通信

本模块回答的客户问题：*我如何证明只有持有正确 SPIFFE ID 的服务才能建立连接，而其他服务——哪怕来自同一集群——都会被拒绝？*

你将部署两个服务（service-a 和 service-b），各自持有独立的 SVID，通过 mTLS 进行通信。然后从 `peer-demo-spire-lab` 命名空间（一个没有注册条目的对照组）发起请求，观察 TLS 握手失败。

== 技术背景

SPIFFE mTLS 工作原理：

. 两个服务各自持有 SPIRE 颁发的 X.509-SVID
. 建立 TLS 连接时，双方互相出示证书
. 每一方用 `bundle.crt`（SPIRE trust bundle）验证对方证书是否由同一 CA 签发
. 可选：通过检查 SAN 中的 SPIFFE ID 决定是否允许连接（授权层）

本实验使用 SPIFFE CSI Driver 挂载 SVID，服务代码直接读取文件，不需要任何密钥管理代码。

== 学习目标

* 部署使用 SVID 建立 mTLS 的微服务
* 验证正向通信：service-a → service-b 成功
* 验证负向控制：peer-demo 命名空间的 Pod → service-b 被拒绝
