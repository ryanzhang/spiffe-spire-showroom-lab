== 证据解读

[cols="1,2,2",options="header"]
|===
| 主题 | 支持的解读 | 需要的证据

| SPIRE 部署健康
| ZeroTrustWorkloadIdentityManager.status.conditions.Ready = True
| `oc get ZeroTrustWorkloadIdentityManager cluster`

| 节点认证完成
| 每个 OCP 节点有一个 k8s_psat 认证的 agent
| `/spire-server agent list`（Facilitator 演示）

| SVID 成功颁发
| Pod 的 `/run/spiffe/tls/tls.crt` SAN 包含正确的 SPIFFE URI
| `openssl x509 -text`

| mTLS 正向通信
| HTTP 200 响应，连接建立时双方均出示了有效 SVID
| 请求日志 + TLS 握手记录

| mTLS 负向控制
| TLS handshake failure，未持有有效 SVID 的客户端被拒绝
| 具体错误消息（TLS alert）
|===

== 本实验不能证明什么

* SPIRE 可以替代 NetworkPolicy — SPIRE 提供身份层，流量路径控制仍需 NetworkPolicy
* X.509-SVID 适合所有场景 — 短连接 REST API 更适合 JWT-SVID
* Trust Domain 联邦 — 跨集群的 Federation 不在本实验范围内
